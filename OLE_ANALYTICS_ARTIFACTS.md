# OLE workbooks and analytics artifacts

## Conclusion

The five extensionless OLE2 files are static game resources, not player-save state. The analytics, push-registration, and WebView artifacts are not required for gameplay progression and should be excluded from a public save.

Evidence is machine-readable in `save-analysis/ole-analytics.json`, generated by `analyze_ole_analytics.py`.

## OLE2 workbooks

All five files are byte-identical between the untouched May 1, 2016 backup and the known-good progressed level-7 snapshot:

| File | Structure | Content | Role |
|---|---:|---|---|
| `clearbox` | 90 sheets; usually 12×30; 8,010 populated cells | Numeric board-cell values | Static board/stage templates |
| `highscore` | 21 sheets; 1,212 populated cells | Numeric board layouts, despite the filename | Static board/test data; not the player's ranking |
| `order` | 1 sheet; 1×60 | Numeric permutation/order | Static ordering table |
| `profile` | 1 sheet; 16×4 | Staff names, job titles, quotes, numeric IDs | Credits data |
| `test` | 1 sheet; 12×30 | Numeric board layout | Static test/template board |

The unchanged SHA-256 values across materially different save states rule these files out as mutable progression state. They may still be runtime assets copied into app-private storage by the APK, but they do not belong in the minimal distributed save.

## Analytics, attribution, and push artifacts

These files encode device- or installation-specific state and should not be redistributed:

| Artifact | Evidence | Classification |
|---|---|---|
| `shared_prefs/mat_id.xml` | Contains a UUID-valued `mat_id` | Mobile-app-tracking installation ID |
| `shared_prefs/mat_queue.xml` | Contains analytics queue size | Analytics queue metadata |
| `shared_prefs/mat_log_id_open.xml` | Mobile-app-tracking preference namespace | Analytics event metadata |
| `shared_prefs/mat_log_id_last_open.xml` | Mobile-app-tracking preference namespace | Analytics event metadata |
| `shared_prefs/Kontagent.xml` | `firstRun`, session sender ID, fingerprint dispatch timestamp | Kontagent analytics session state |
| `files/kontagentCheck_v2_2.dat` | Kontagent-named SEED-encrypted profile | Analytics initialization state |
| `shared_prefs/e30b431a9b2d47948fed9f6a5602fa91.13.xml` | Kontagent API-key-derived name | Analytics endpoint/configuration state |
| `databases/e30b431a9b2d47948fed9f6a5602fa91` | `api_calls` table has zero rows | Empty Kontagent request queue |
| `shared_prefs/OL_Prefs_Keys.xml` | Tracking ID plus current and old GCM device tokens | Attribution/push installation identity |
| `shared_prefs/com.google.android.gcm.xml` | GCM registration preferences | Push registration state |
| `files/AppEventsLogger.persistedevents` | Facebook App Events serialized persistence file | Analytics event persistence |

The 2016 backup contains real historical tracking IDs and GCM registration tokens. Public packaging must omit them rather than replacing them with dummy values: the libraries can create fresh local state if invoked, while the patched game does not need those identifiers for offline gameplay.

## Empty browser databases

The detected WebView databases contain schema only:

- `webview.db`: `formurl`, `formdata`, `httpauth`, and `password` all have zero rows.
- `Web Data`: autofill, credit-card, address, email, and phone tables all have zero rows; only Chromium schema metadata is present.

They are runtime cache scaffolding, not save data, and should be omitted.

## Public-save policy

Include only the validated gameplay bootstrap records and the seed marker listed in `minimal-public-save/manifest.json`. Exclude:

- all five OLE workbooks;
- all analytics, attribution, Facebook, Kontagent, and GCM artifacts above;
- WebView databases and caches;
- package-manager/Titanium metadata that is not required by the chosen installer.

This classification is independent of the leaderboard response-pool fix: the mutable ranking/request records are CCrypt2 files in `files/`, not the OLE workbook named `highscore`.
