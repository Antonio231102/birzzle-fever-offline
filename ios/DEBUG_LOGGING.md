## Installed Windows tools and scoped iOS 6 TLS

The [MSYS2 mingw64 libimobiledevice package](https://packages.msys2.org/packages/mingw-w64-x86_64-libimobiledevice) installed `idevice_id.exe`, `ideviceinfo.exe`, `idevicepair.exe`, `idevicesyslog.exe`, and `idevicecrashreport.exe` under `C:\msys64\mingw64\bin`. MSYS2 core and packages were updated. No Apple USB drivers, device security settings, saves, or game files were changed.

On this legacy iPad, plain OpenSSL 3 client pairing returned `SSL error (-5)` even though `idevicepair pair` succeeded. ProductVersion is accessible via `ideviceinfo -s`, but a normal encrypted session failed. The per-process `ios/openssl-ios6.cnf` sets TLS 1.0, security level 0, and `UnsafeLegacyRenegotiation`; with **only** `OPENSSL_CONF` on the libimobiledevice child processes, pairing validates and normal `ideviceinfo` reports iPad2,1 / iOS 6.1.3. This intentionally relaxes **those local USB client processes**, not Windows, Apple Mobile Device service, the iPad, or any global OpenSSL policy. Do not apply this configuration to general web connections.

## Non-logging USB preflight

Run from the project root before a manual test:

```powershell
python ios/capture_ios_logs.py --check
```

This enumerates exactly one USB iOS device, verifies pairing and the expected iPad 2 / iOS 6.1.3 identity, and exits **without** reading syslog, crash reports, app data, or launching the game. If more than one iOS device is attached, use `--udid <UDID>` from `C:\msys64\mingw64\bin\idevice_id.exe -l`; the tool does not guess. The script locates the installed tools and applies its TLS configuration only to its child processes.

## One-command manual capture — only after explicit operator readiness

First print a pre-flight alert naming iPad 2 / Birzzle Fever 1.0.4 and visual signals (loading, offline sign-in, main menu, gameplay, freeze/crash); obey the repository's manual-test readiness gate. Then, from the project root in an **interactive** terminal:

```powershell
python ios/capture_ios_logs.py --capture --operator-ready --duration 300
```

Start the capture **before** the operator manually launches the game. `--operator-ready` is required and must only be supplied after the manual readiness gate; invoking `--capture` alone refuses to start. The script does not tap, navigate, launch, erase, or reset anything on the iPad. Press Enter when the operator reports a crash or completes the test; it also stops at the duration limit and records why it stopped. The installed `idevicesyslog` lacks `--output`, so the script captures stdout directly to `ios/captures/<UTC-session>/device-syslog.txt`, then produces an app-focused excerpt. It copies crash reports with `idevicecrashreport -k -e` into that same ignored directory and leaves originals on the iPad. The installed crash client lacks `--filter`, so copies may include **other apps and older crashes**; do not treat every copied report as evidence from this session and **do not share raw captures**. The session JSON records scoped metadata and the crash copy result, not the app's private save.

Only analyze `BirzzleFever HB` / `com.halfbrick.birzzlefever` lines, related `ReportCrash` and SpringBoard termination messages, and the matching `.crash` report's exception, crashed thread, and Binary Images/slide. Raw syslog can include other users/apps and stays local under `ios/captures/`, excluded by `ios/.gitignore`. Do not clear device logs. `adb logcat` and Android's buffer-clearing/bootstrap sequence do not apply to iOS 6. If syslog relay fails even though pairing validates, stop and inspect the client stderr in that session before attempting any SSH/syslogd fallback; do not assume `/var/log/syslog` exists.

The app itself logged a device token and a member identifier during the first offline-startup trial; those values were redacted in the derived app-focused capture, while the original ignored raw syslog remains private. New `capture_ios_logs.py` app-focused excerpts redact both observed labels automatically. Never print matching raw account lines, token values or copied crash filenames in diagnostics.
